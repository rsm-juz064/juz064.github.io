MaxDiff Analysis of MSBA Class Preferences

Counts, MLE, and Bayesian Estimation of the MNL Model

Author

Junzhe Zhao

Published

May 28, 2026

Introduction

MaxDiff, also called Best-Worst Scaling, is a survey method for measuring relative preferences. In each task, a respondent sees a small set of alternatives and chooses the option they like most and the option they like least. In this assignment, the alternatives are the 10 UCSD Rady MSBA core classes.

MaxDiff is useful because people are often better at making trade-offs than assigning absolute numerical scores. A 1–10 rating scale can be affected by scale-use bias: one respondent may give nearly everything an 8 or 9, while another may use the full range. MaxDiff forces respondents to make comparisons, which creates clearer information about relative preference.

This analysis estimates student preferences for the MSBA classes in three ways. First, I use a simple counts analysis based on how often each class was chosen best minus how often it was chosen worst. Second, I estimate a multinomial logit model by maximum likelihood. Third, I estimate the same MNL model with a Bayesian Metropolis-Hastings sampler. I expect the methods to agree on the broad ranking of classes, especially for the strongest and weakest items, while differing slightly for classes in the middle of the ranking.

Counts Analysis

The counts analysis is the simplest summary of MaxDiff data. For each item, I compute the percentage of times it was chosen as best and the percentage of times it was chosen as worst. The score is:

[ _j = %_j - %_j ]

A positive score means the class is more often chosen best than worst. A negative score means the opposite. This method is intuitive and easy to explain, but it does not explicitly model the probabilistic choice process.

Bootstrap confidence intervals for counts scores

To add uncertainty to the descriptive counts analysis, I resample respondents with replacement. For each bootstrap sample, I recompute the counts score for every item. The 2.5th and 97.5th percentiles form a 95% bootstrap confidence interval.

Code 
def compute_counts_score(df):
    shown_b = df.groupby("Item").size()
    best_b = df.loc[df["Response"] == 1].groupby("Item").size()
    worst_b = df.loc[df["Response"] == -1].groupby("Item").size()

    out = pd.DataFrame({"shown": shown_b, "best": best_b, "worst": worst_b}).fillna(0)
    out["score"] = out["best"] / out["shown"] - out["worst"] / out["shown"]
    return out["score"].reindex(labels["Item"]).to_numpy()

respondents = valid_design["Record ID"].unique()
B = 1000
boot_scores = np.zeros((B, J_total))

for b in range(B):
    sampled_ids = np.random.choice(respondents, size=len(respondents), replace=True)
    sampled_parts = []
    for new_id, rid in enumerate(sampled_ids):
        temp = valid_design.loc[valid_design["Record ID"] == rid].copy()
        temp["Boot ID"] = new_id
        sampled_parts.append(temp)
    boot_df = pd.concat(sampled_parts, ignore_index=True)
    boot_scores[b, :] = compute_counts_score(boot_df)

From MaxDiff Data to MNL Choices

The multinomial logit model treats each MaxDiff task as a sequence of choices. First, the respondent chooses the best item from the set of four shown items. Then, after removing the chosen best item, the respondent chooses the worst item from the remaining three items using utilities with the sign reversed.

For a best choice from shown set (S):

[ P(=j) = ]

For the worst choice after the best item is removed:

[ P(=j ) = ]

Only relative utilities are identified. Adding the same constant to every () does not change the choice probabilities. Therefore, I set (_1 = 0) and estimate the remaining nine coefficients.

MNL via Maximum Likelihood

The log-likelihood sums the log probability of the best choice and the log probability of the worst choice for every task:

[ () = _{tasks} ]

I use logsumexp for numerical stability and maximize the likelihood using BFGS.

Code 
def make_full_beta(beta_free):
    """Insert beta_1 = 0 for identification."""
    beta = np.zeros(J_total)
    beta[1:] = beta_free
    return beta


def neg_log_likelihood(beta_free):
    beta = make_full_beta(beta_free)

    # Best-choice likelihood from the 4 shown items.
    utilities = beta[shown_items]
    best_ll = beta[best_items] - logsumexp(utilities, axis=1)

    # Worst-choice likelihood from the remaining items after removing the best item.
    remaining_mask = shown_items != best_items[:, None]
    neg_utilities = np.where(remaining_mask, -beta[shown_items], -np.inf)
    worst_ll = -beta[worst_items] - logsumexp(neg_utilities, axis=1)

    return -(best_ll + worst_ll).sum()

The optimizer reaches the same likelihood even if it reports a precision-loss warning, which can occur with numerical gradients. For standard errors, I compute a numerical Hessian of the minimized negative log-likelihood at the optimum and then invert that Hessian. This is the Python equivalent of using the inverse of the negative Hessian of the log-likelihood.

Code 
def finite_difference_hessian(f, x, eps=1e-4):
    """Central finite-difference Hessian for a scalar objective."""
    x = np.asarray(x, dtype=float)
    n = len(x)
    H = np.zeros((n, n))
    fx = f(x)

    for i in range(n):
        ei = np.zeros(n)
        ei[i] = eps
        H[i, i] = (f(x + ei) - 2 * fx + f(x - ei)) / eps**2

        for j in range(i + 1, n):
            ej = np.zeros(n)
            ej[j] = eps
            H_ij = (
                f(x + ei + ej)
                - f(x + ei - ej)
                - f(x - ei + ej)
                + f(x - ei - ej)
            ) / (4 * eps**2)
            H[i, j] = H_ij
            H[j, i] = H_ij

    return H

MNL via Bayesian Estimation

The Bayesian version estimates the same utility model, but it combines the likelihood with a prior distribution:

[ ( y) L()() ]

I use a weakly informative normal prior:

[ _j N(0, 10) ]

The prior is centered at zero and has standard deviation about 3.16, which is broad enough not to dominate the data.

Code 
def log_likelihood(beta_free):
    return -neg_log_likelihood(beta_free)


def log_prior(beta_free):
    return -0.5 * np.sum(beta_free ** 2 / 10)


def log_posterior(beta_free):
    return log_likelihood(beta_free) + log_prior(beta_free)

Metropolis-Hastings sampler

Code 
def mh_sampler(beta0, n_iter=20000, step=0.08):
    beta = beta0.copy()
    draws = np.zeros((n_iter, len(beta0)))
    current_lp = log_posterior(beta)
    accept = 0

    for t in range(n_iter):
        proposal = beta + np.random.normal(0, step, size=len(beta0))
        proposal_lp = log_posterior(proposal)

        if np.log(np.random.rand()) < proposal_lp - current_lp:
            beta = proposal
            current_lp = proposal_lp
            accept += 1

        draws[t, :] = beta

    return draws, accept / n_iter

The Bayesian results closely match the MLE results. This makes sense because the prior is weak and the data contain many valid choice observations. The posterior standard deviations are also close to the MLE standard errors for most coefficients. Noticeable differences are small and mostly occur for the reference-normalized scale and for items with wider uncertainty. The main advantage of the Bayesian approach is that uncertainty intervals for shares are easy to compute: I transform every posterior draw into a share and then summarize the resulting distribution.

The three methods agree most strongly at the top and bottom of the ranking. MGTA 495 Marketing Analytics is the clear favorite across all methods. Classes such as MGTA 444 Analytics Consulting, MGTA 451 Marketing/Finance/Operations, and MGTA 403 AI Math, Programming, & Analytics are consistently near the bottom.

The methods differ more in the middle. This is expected because middle-ranked items have similar utilities, so small differences in the treatment of the choice process can flip their order. The MNL model adds value over counts because it models each choice set directly and uses information from both chosen and non-chosen items. The Bayesian model adds value over MLE because it makes uncertainty in derived quantities, such as preference shares, straightforward to summarize.

Discussion

Substantively, the strongest result is that students in this survey show high preference for MGTA 495 Marketing Analytics. Several other analytics-oriented classes also perform well, including MGTA 453 Business Analytics, MGTA 455 Customer Analytics, and MGTA 452 Large Data. Lower-ranked classes appear to be less preferred in this sample, although this does not necessarily mean they are less valuable academically. Preference may reflect timing, instructor familiarity, prior experience, perceived workload, or career goals.

Methodologically, the counts analysis is best for a quick descriptive dashboard. It is transparent and easy to explain. The MLE MNL model is better when we want a formal statistical model of the choice process and interpretable preference shares. The Bayesian MNL model is useful when we care about uncertainty, especially uncertainty around transformed quantities such as preference shares.

The main caveat is that this is a self-selected sample of MSBA students, so the results may not generalize to all students or future cohorts. If I had more time, I would extend the Bayesian model into a hierarchical model to estimate individual-level preference heterogeneity and examine whether preferences differ by student background, career interest, or prior coursework.
